### Language Switch (The Bug)

**Trace:**

```
1. User clicks EN/HI toggle
   → AuthContext.setLanguage('hi')
   → localStorage.setItem('np_lang', 'hi')
   → React context re-renders

2. LearnHub reads: const { language } = useAuth()
   → All UI strings switch (tabs, buttons, labels) ✅

3. Content fetched: GET /api/learn/content/:exam/:subject/:topic/:subtopic
   → Returns FULL document: { introduction, detailedExplanation, ... }
   → These fields contain: "English text ===HINDI=== हिंदी पाठ"
   → Backend does NOT filter by language ✅ (correct — client splits)

4. ContentReader renders:
   → getLangText(content.introduction, language)
   → Splits on ===HINDI===, returns correct part ✅ (works for intro)

5. BUT: PYQ tab (PYQCard component)
   → language === 'hi' && q.question?.hi ? q.question.hi : q.question?.en  ✅
   → ALSO shows English version below Hindi (always):
     "language === 'hi' && q.question?.hi && q.question?.en → show EN too"
   → This is the "mixed content" bug. Hindi mode shows both EN and HI.

6. BUT: Options in PYQ cards:
   → optText = language==='hi' && opt.hi ? opt.hi : opt.en ✅
   → optSubText = language==='hi' && opt.hi ? opt.en : opt.hi ❌
   → In Hindi mode: PRIMARY is Hindi, but SECONDARY shows English below it.
   → Mixed paragraphs confirmed.

7. BUT: Explanation in revealed PYQ:
   → Hindi mode shows Hindi explanation ✅
   → THEN shows English explanation below (always): "q.explanation.en" ❌
   → Double-language display confirmed.
```

**Root Cause of Language Bug:**
The PYQ card intentionally shows both languages as a "bilingual" feature, but this violates the mission requirement of "NO MIXED CONTENT". The `getLangText()` helper works correctly everywhere else. The bug is isolated to `PYQCard` component (lines 588-639 of LearnHub.jsx).

## Part 3 — Language Fix Plan

### What Works (Keep)
- `getLangText(text, language)` — correctly splits `===HINDI===` → ✅ Keep as-is
- `language` from `useAuth()` — context is correct ✅
- Study Notes tab — all fields use `getLangText()` correctly ✅

### What's Broken (Fix)
- **PYQCard**: Shows English secondary text below Hindi primary (lines 588-592, 635-639)
- **PYQCard Options**: Shows both `opt.hi` and `opt.en` simultaneously (line 597)
- **PYQCard Explanation**: Shows both EN and HI versions (lines 623-639)

### Fix Strategy
Remove the "bilingual secondary" display from PYQCard entirely:

```jsx
// BEFORE (broken — shows both languages):
{language === 'hi' && q.question?.hi && q.question?.en && (
  <p style={{ color: 'muted' }}>{q.question.en}</p>  // ❌ remove
)}

// AFTER (clean — single language):
// Show ONLY the primary language text. No secondary.
const questionText = language === 'hi' && q.question?.hi
  ? q.question.hi
  : q.question?.en;
// Render: <p>{questionText}</p>  — done.
```

Same fix applies to options and explanation.

### Step 2: Consolidate DB Records (20,328 → ~726)

Merge the 28 "Part N" records per real topic into **1 consolidated record** per real topic.

Merge strategy:
- `introduction` = best intro from Part 1
- `detailedExplanation` = concatenate Parts 2–5 (theory) 
- `concepts` = union of all parts
- `importantFacts` = union of all parts (deduped)
- `examples` = union of all parts (deduped)
- `tables` = union of all parts
- `revisionNotes` = best from Part 10 (Quick Revision)
- `pyqs` = union of all parts (deduped by question text)

Result: ~726 rich records (1 per real topic) instead of 20,328 thin template records.

### Step 3: Fix LearnHub Frontend

**LearnHub.jsx changes:**
1. **Navigation UX** — Replace flat subtopic list with topic cards; clicking a topic opens a full-page learning module
2. **Language fix** — Remove secondary-language display from PYQCard
3. **Content page** — Redesign ContentReader as a structured learning page with named sections (not generic tabs)

**No backend changes needed** — the API route `/api/learn/content/:exam/:subject/:topic/:subtopic` stays the same.

### Step 4: Rebuild Content Quality (Phase 5 of Quality Mission)

After consolidation, each of the ~726 records needs coaching-grade content written. This is the content rebuild phase.
